# 实验结果与参数分析

本文件记录 `prototype.py` 在 1212 条 FF7 词条上的可复现实验结果、消融、参数敏感性、失败案例和推荐默认值。算法设计见 `ALGORITHM.md`。

## 1. 结论摘要

| 指标 | 结果 |
|---|---:|
| 测试用例总数 | 55 |
| 通过 | 55 / 55 = **100%** |
| 需要 top1 的用例 | 47 / 47 = **100%** |
| “期望在 topN”用例 | 2 / 2 = **100%** |
| 仅检查候选数的用例 | 6 / 6 = **100%** |
| 核心验收：`lkcc` top1 长句 | 通过（0.8708，第二名 0.5699） |
| 核心验收：`lienuo`/`leino`/`leiknuo` top1 雷诺 | 通过（0.9862 / 0.9924 / 0.9874） |
| 核心验收：模糊音 zh/z、ch/c、sh/s、ng/n | 通过 |
| 核心验收：多音字 9 类 | 通过 |
| 核心验收：无匹配仍返回 N 个 | 通过 |

推荐默认配置：

- **通道权重**：`exact=1.0, fuzzy_exact=1.0, initial_exact=1.0, prefix=1.0, fuzzy_prefix=0.9, edit=0.9, edit_fuzzy=0.7, syllable=1.1, initial_prefix=0.9, initial_subseq=1.7, keyword_subseq=0.5, bigram=0.25`
- **切分/读音**：`max_segmentations=6`，`max_variants=24`，`alt_reading_weight=0.82`，`misread_weight=0.55`，`reading_penalty=0.12`
- **长度/前缀**：`length_penalty=0.02`，`prefix_exponent=0.6`，`compact_exponent=0.9`
- **候选数**：`top_n=5`（建议 5 或 9）
- **模糊**：`zh_z/ch_c/sh_s/ng_n = true`；`n_l/r_l/f_h = false`（预留）
- **回退标记**：`fallback_threshold=0.5`（最大通道分数低于此值只做 UI 提示，不影响输出）

## 2. 运行环境与复现方式

- 操作系统：Windows 10 x64
- Python：3.14.7
- 词典：`../dict.txt`，UTF-16 LE BOM，1212 条
- 运行数据：`phrases.tsv`，1212 条，`build_phrases.py --check` 通过
- 原型只使用 Python 标准库；`build_phrases.py` 额外需要 `pypinyin`（仅重建数据时）

复现命令（在 `experiments/algorithm-design` 下）：

```bash
# 重建拼音数据（可选；需要 pypinyin）
python build_phrases.py

# 单条查询
python prototype.py --input lkcc --top 5 --explain
python prototype.py --input lienuo --top 5 --explain
python prototype.py --input qwertyuiop --top 9 --json

# 完整测试
python prototype.py --eval test_cases.json

# 消融
python prototype.py --eval test_cases.json --ablation

# 参数敏感性（会写 sensitivity_results.json）
python sensitivity.py
```

原型单条查询在本机约 **0.4–0.5 秒**（1212 条、全部通道、含解释信息）；Lua 侧需要按 `ALGORITHM.md` 第 9 节做缓存和粗筛。

## 5. 消融分析

命令：

```bash
python prototype.py --eval test_cases.json --ablation
```

结果（55 条用例；`pass` 为全部检查，`top1` 为 47 条 top1 用例，`inTopN` 为 2 条“期望在 topN”用例）：

| 配置 | pass | top1 | inTopN | 说明 |
|---|---:|---:|---:|---|
| `full` | **1.000** | **1.000** | **1.000** | 默认配置 |
| `no_initial` | 0.927 | 0.936 | 0.500 | 关闭全声母/声母前缀/声母子序列 |
| `no_keyword` | 0.927 | 0.936 | 0.500 | 关闭声母子序列 + 字母关键词 |
| `no_syllable` | 0.982 | 0.979 | 1.000 | 关闭音节对齐 |
| `no_edit` | 1.000 | 1.000 | 1.000 | 关闭两个字母编辑通道 |
| `exact_only` | 0.818 | 0.808 | 0.500 | 只保留 exact + prefix |
| `no_fuzzy` | 1.000 | 1.000 | 1.000 | 关闭全部模糊开关和模糊通道 |
| `keyword_heavy` | 1.000 | 1.000 | 1.000 | `initial_subseq` 权重 2.6 |
| `edit_heavy` | 0.964 | 0.957 | 1.000 | `edit` 权重 1.8 |
| `short_bias` | 1.000 | 1.000 | 1.000 | `length_penalty` 0.08 |

### 5.1 关键结论

1. **声母/关键词通道不可替代**：关闭后 `lkcc`、`wmhlkcd`、`wmhl`、`kcc` 等用例失败，pass 降到 0.927。具体失败：
   - `initials_subseq_lkcc` → top1 凌空破；
   - `initials_prefix_wmhlkcd` → top1 野马航空；
   - `initials_prefix_wmhl` → top1 无名者；
   - `keyword_kcc_in_top5` → 目标长句掉出 top5。
2. **音节对齐不可替代**：关闭后 `nuolei` 的 top1 变成 诺艾米；`nuolei` 的块换位无法只靠字母编辑处理。
3. **字母编辑通道在本测试集上是冗余的**：关闭后仍 100%。原因是 6 个雷诺错误输入都能被音节 DP 的替换/插入/换位覆盖。但字母编辑对“无法切成合法音节”的任意串仍是必要的兜底；建议保留，不要因为本测试集通过就删除。
4. **精确+前缀远远不够**：`exact_only` 只有 0.818；所有 typo、声母、关键词用例都失败。
5. **模糊开关关闭仍 100%**：说明近似通道（编辑距离、音节对齐）本身能兜住这些模糊输入；模糊通道的价值是提高置信度/扩大召回，而不是唯一通路。正式版建议保持开启，以符合用户对模糊音的预期。
6. **权重过敏点**：`edit=1.8` 会把 `nuolei` 推给 诺艾米，并让 `danshou` 输给 尖喙兽；`syllable` 太低（0.4/0.8）也会让 `nuolei` 失败。默认 `edit=0.9, syllable=1.1` 位于稳定区间。

## 6. 参数敏感性

命令：

```bash
python sensitivity.py
```

脚本对“只影响融合权重”的参数使用通道分数缓存，对“影响通道分数”的参数做完整重算。完整数据见 `sensitivity_results.json`。

### 6.1 通道权重

| 参数 | 取值 | pass | top1 | inTopN |
|---|---|---:|---:|---:|
| `initial_subseq` | 0.8 / 1.2 / 1.7 / 2.2 / 2.6 | 1.000 | 1.000 | 1.000 |
| `syllable` | 0.4 | 0.982 | 0.979 | 1.000 |
|  | 0.8 | 0.982 | 0.979 | 1.000 |
|  | **1.1（默认）** | **1.000** | **1.000** | **1.000** |
|  | 1.5 | 1.000 | 1.000 | 1.000 |
|  | 2.0 | 0.982 | 0.979 | 1.000 |
| `edit` | 0.3 / 0.6 / **0.9（默认）** / 1.0 / 1.1 | 1.000 | 1.000 | 1.000 |
|  | 1.3 | 0.982 | 0.979 | 1.000 |
|  | 1.8 | 0.964 | 0.957 | 1.000 |
| `fuzzy_exact` | 0.3 / 0.6 / **1.0（默认）** / 1.5 | 1.000 | 1.000 | 1.000 |
| `bigram` | 0.0 | 0.982 | 0.979 | 1.000 |
|  | 0.15 / **0.25（默认）** / 0.5 | 1.000 | 1.000 | 1.000 |

细粒度补充（同一套用例）：

- `syllable` 在 **1.0–1.5** 全部通过；0.8 和 2.0 各失败 1 条：
  - 0.8：`nuolei` → 诺艾米；
  - 2.0：`danshou` → 尖喙兽。
- `edit` 在 **0.3–1.1** 全部通过；1.3 和 1.8 各失败 `nuolei`/`danshou`。
- `initial_subseq` 在 0.8–2.6 完全平坦，说明 `lkcc` 的召回不依赖该权重的精确值。
- `bigram=0` 只失败 `nuolei`，说明二元组主要提供回退/弱证据，默认 0.25 有正向作用。
- `fuzzy_exact` 0.3–1.5 完全平坦；模糊通道不是 top1 的决定性因素，但保留它符合需求 A。

### 6.2 结构性参数

| 参数 | 取值 | pass | top1 | inTopN |
|---|---|---:|---:|---:|
| `length_penalty` | 0.0 / **0.02** / 0.05 / 0.08 / 0.12 | 1.000 | 1.000 | 1.000 |
| `max_segmentations` | 3 / **6** / 12 | 1.000 | 1.000 | 1.000 |
| `fuzzy_enabled` | 0（全部关闭） | 1.000 | 1.000 | 1.000 |

说明：

- `length_penalty` 在 0–0.12 完全平坦；默认 0.02 是“轻微偏好短词”，不是硬阈值。
- `max_segmentations` 3/6/12 都通过；6 是性能与歧义保留的折中。
- 关闭全部模糊开关仍 100%，但会降低模糊输入的分数裕量；正式版建议开启。

### 6.3 推荐默认值及理由

| 参数 | 推荐 | 理由 |
|---|---:|---|
| `syllable` | 1.1 | 稳定区间 1.0–1.5 的低端；保证 `nuolei`，又不让长词条过度占优 |
| `edit` | 0.9 | 稳定区间 0.3–1.1；1.3 以上开始伤害 `nuolei`/`danshou` |
| `initial_subseq` | 1.7 | 0.8–2.6 平坦；1.7 对 `lkcc` 有足够权重，同时不压过精确匹配 |
| `bigram` | 0.25 | 0 会伤害 `nuolei`；0.15–0.5 稳定 |
| `length_penalty` | 0.02 | 0–0.12 平坦；0.02 仅轻微偏好短词 |
| `max_segmentations` | 6 | 3/6/12 都通过；6 兼顾歧义和性能 |
| `fuzzy_exact` | 1.0 | 0.3–1.5 平坦；保持需求 A 的显式行为 |
| `fallback_threshold` | 0.5 | 最大通道分数低于 0.5 标记“无强证据”；不影响返回数量 |

## 7. 失败案例与分析

### 7.1 `kcc`：短关键词的合法歧义

```
kcc → 狂野驰骋 0.9619
      混成昆虫 0.9309
      我们会立刻彻底铲除你们！ 0.8214
```

原因：

- `kcc` 只有 3 个字母，短词“狂野驰骋”（`kuangyechicheng`，模糊声母 `k y c c`）的声母子序列更紧凑；
- 长句的 `phrase_cov=3/11` 很低，`compact` 也不如 4 字母的 `lkcc`。

结论：这不是算法 bug，而是输入本身歧义。需求明确以 `lkcc` 为关键词示例；`kcc` 只要求进入 top5，测试用例 `keyword_kcc_in_top5` 已覆盖。

### 7.2 `shenluoshen`：多一个音节

```
shenluoshen → 神罗兵 0.9604
               神罗 0.9563
               神罗战士 0.9450
```

“神罗兵”与查询同为 3 音节，只需替换最后一个音节；“神罗”需要额外插入一个音节，归一化后略低。原词仍在 top3。若希望原词优先，可提高 `prefix` 权重或增加“查询以词条全拼为前缀”的 bonus；当前不做，以避免长词条前缀过度占优。

### 7.3 `shanshou`：低频异读 + 长词条部分输入

```
shanshou → 蛇鸡兽 0.9222
           深渊手镯 0.8913
           尖喙兽 0.8611
           ...
单手是枪的男人 不在 top10
```

“单手是枪的男人”的“单”可读 `shan`（第 3 读音，权重 0.70），但 `shanshou` 只覆盖 7 字长句的前 2 个音节：

- 覆盖率 `2/7` 很低；
- 异读权重低；
- 短词“蛇鸡兽”（`shejishou`）在编辑距离/音节对齐上更接近。

这是“部分输入 + 低频异读 + 长词条”的三重劣势。若实际用户经常这样输入，可提高 `prefix` 权重或给“首音节为异读且后续匹配”的情况加通道；当前默认优先保证短词/精确匹配的稳定性。

### 7.4 噪声或饱和

多个通道同时命中时，融合分数会接近 1：

- `神罗` 精确 = 1.0000；
- `神罗兵` = 0.9941（prefix 0.762 + bigram 0.750 + keyword 0.679 + syllable 0.667）。

排序仍正确，但分数差距只有 0.006。若 UI 展示分数，建议做单调压缩或只显示通道标签。

### 7.5 多音字过度生成

`区` 的 `ou`、`单` 的 `chan/shan`、`解` 的 `xie` 等异读扩大召回，也可能误命中。当前用读音权重（0.82/0.76/…）和 `reading_penalty=0.12` 抑制。若实际误命中过多：

- 只保留常用异读白名单；
- 降低 `alt_reading_weight`；
- 对第 3 个及以后异读设更低权重或禁用。

### 7.6 误读表是人工的

`蒂→ti`、`诺→ruo` 是人工加入的；`岑→qin` 因词典无“岑”不产生影响。误读表无法覆盖所有“有边读边”，需要后续按用户反馈扩充。建议误读权重固定在 0.4–0.6，且只在没有规范读音精确匹配时作为补充证据。

### 7.7 切分歧义 `xian`

`xian` 同时保留 `xian` 和 `xi'an`。若词典同时有“先”和“西安”，两者都会候选；当前词典没有“西安”，不构成实际问题。Lua 侧应保留多切分，不要只取最长匹配。

### 7.8 无调与同音词

无调全拼无法区分声调，同音词完全依赖词条长度、读音权重和通道证据。当前 1212 条冲突有限；扩充词典后需要词频/上下文模型。

### 7.9 性能风险

Python 原型约 0.4–0.5 秒/查询。Lua 侧若逐键执行全部通道，可能超过 100ms。必须：

- 预加载数据；
- 缓存音节替换代价；
- 限制切分数（默认 6）；
- `|n-m|>4` 时跳过音节 DP；
- 在 `experiments/lua-probe` 中实测并做粗筛。
